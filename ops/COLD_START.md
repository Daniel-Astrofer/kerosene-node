# Cold start procedure — new network bootstrap

This document describes the step-by-step procedure for bootstrapping a new
Kerosene network from scratch, starting with infrastructure provisioning and
ending with a verified multi-node quorum.

## Prerequisites

### Infrastructure

- One Linux server per node, each with:
  - Tor daemon installed (`apt install tor` or equivalent)
  - Rust toolchain 1.88 (for compilation) or a pre-compiled binary
  - At least 1 GB RAM, 10 GB disk
  - Outbound HTTPS access (for Tor reachability)
- A secure out-of-band channel for initial configuration distribution (SSH,
  encrypted USB, or equivalent)

### Keys and certificates

| Artifact | Per-node or shared | Generated by | Lifetime |
|---|---|---|---|
| Ed25519 root identity key | Per-node | `kerosene-node-keygen` | Permanent (rotate on compromise) |
| TLS server certificate | Per-node | Operator / PKI | 1 year |
| TLS server key | Per-node | Operator / PKI | 1 year |
| TLS client CA certificate | Shared | Operator / PKI | 5 years |
| TLS client identity (cert + key) | Per-node | Operator / PKI | 1 year |
| Genesis trust bundle | Shared | Operator | Permanent (update via manifest) |

### Tor onion services

For each node:

```bash
# In /etc/tor/torrc:
HiddenServiceDir /var/lib/tor/kerosene-node/
HiddenServicePort 80 127.0.0.1:8800
```

After starting/reloading Tor, read the hostname:

```bash
cat /var/lib/tor/kerosene-node/hostname
# → abcdefghijklmnopqrstuvwxyz234567abcdefghijklmnopqrstuvwxyz234.onion
```

The onion hostname is the node's discoverable endpoint. It must match the
TLS certificate SAN.

## 1. Generate member identities

Run once per node, on a secure offline machine if possible:

```bash
cargo run --locked -p kerosene-node --bin kerosene-node-keygen -- \
  <network-id> /secure/member-<name>/identity.key
```

Record the printed `member_id` and `root_public_key` for each node. The
identity key file is created with mode `0600`. Back it up securely — it
cannot be recovered.

## 2. Create the GenesisTrustBundleV1

Create `genesis-trust-bundle.json`:

```json
{
  "contract_version": "1.0",
  "network_id": "<network-id>",
  "bank": {
    "threshold": 2,
    "members": [
      {
        "member_id": "<bank-node-a-member-id>",
        "root_public_key": "<bank-node-a-public-key>"
      },
      {
        "member_id": "<bank-node-b-member-id>",
        "root_public_key": "<bank-node-b-public-key>"
      },
      {
        "member_id": "<bank-node-c-member-id>",
        "root_public_key": "<bank-node-c-public-key>"
      }
    ]
  },
  "vault": {
    "threshold": 2,
    "members": [
      {
        "member_id": "<vault-node-a-member-id>",
        "root_public_key": "<vault-node-a-public-key>"
      },
      {
        "member_id": "<vault-node-b-member-id>",
        "root_public_key": "<vault-node-b-public-key>"
      },
      {
        "member_id": "<vault-node-c-member-id>",
        "root_public_key": "<vault-node-c-public-key>"
      }
    ]
  },
  "created_at_epoch_ms": <current-unix-ms>
}
```

Validate the bundle:

```bash
cargo run -p kerosene-rsctl -- membership verify \
  --manifest genesis-trust-bundle.json \
  --trust-bundle genesis-trust-bundle.json
```

## 3. Provision TLS material

### Generate a CA for client mTLS

```bash
# Generate CA key and certificate
openssl genpkey -algorithm ED25519 -out client-ca.key
openssl req -x509 -new -key client-ca.key -days 1825 -out client-ca.pem \
  -subj "/CN=Kerosene Client CA/<network-id>"
```

### Generate per-node server certificate

```bash
# Generate server key and CSR
openssl genpkey -algorithm ED25519 -out node-a.key
openssl req -new -key node-a.key -out node-a.csr \
  -subj "/CN=<node-a-onion-hostname>"

# Sign with the client CA (or a separate server CA)
openssl x509 -req -in node-a.csr -CA client-ca.pem -CAkey client-ca.key \
  -days 365 -out node-a.pem -extfile <(printf "subjectAltName=DNS:<node-a-onion-hostname>")
```

### Generate per-node client identity

```bash
# Client cert for outbound mTLS
openssl genpkey -algorithm ED25519 -out node-a-client.key
openssl req -new -key node-a-client.key -out node-a-client.csr \
  -subj "/CN=node-a"
openssl x509 -req -in node-a-client.csr -CA client-ca.pem -CAkey client-ca.key \
  -days 365 -out node-a-client.pem
cat node-a-client.pem node-a-client.key > node-a-client-identity.pem
```

## 4. Node-by-node startup sequence

### 4.1 Start the first Bank/Core node

This node is started first with no discovery endpoints. It will be
`ACTIVE_LOCAL_WAITING_FOR_PEERS`.

```bash
KEROSENE_NETWORK_ID=<network-id> \
KEROSENE_DISCOVERY_PLANE=bank \
KEROSENE_NODE_ONION_ENDPOINT=https://<node-a-onion>.onion:8800 \
KEROSENE_GENESIS_TRUST_BUNDLE=/path/to/genesis-trust-bundle.json \
KEROSENE_TLS_CERT_PATH=/path/to/node-a.pem \
KEROSENE_TLS_KEY_PATH=/path/to/node-a.key \
KEROSENE_TLS_CLIENT_CA_PATH=/path/to/client-ca.pem \
KEROSENE_TLS_CLIENT_IDENTITY_PEM=/path/to/node-a-client-identity.pem \
KEROSENE_TOR_SOCKS_PROXY=socks5h://127.0.0.1:9050 \
  cargo run --locked --features production -p kerosene-node
```

### 4.2 Verify the first node

```bash
curl --cert node-a.pem --key node-a.key --cacert client-ca.pem \
  https://<node-a-onion>.onion:8800/live
# → 200 OK

curl ... /ready-local
# → 200 OK

curl ... /ready-member
# → 200 OK (its identity is in the genesis bundle)

curl ... /ready-quorum
# → 503 Service Unavailable (not enough peers yet)
```

### 4.3 Start the second Bank/Core node

This node has genesis endpoints pointing to node A. After discovery, it
should reach quorum (2-of-3 threshold with 2 live nodes).

```bash
KEROSENE_NETWORK_ID=<network-id> \
KEROSENE_DISCOVERY_PLANE=bank \
KEROSENE_NODE_ONION_ENDPOINT=https://<node-b-onion>.onion:8800 \
KEROSENE_GENESIS_TRUST_BUNDLE=/path/to/genesis-trust-bundle.json \
KEROSENE_GENESIS_ENDPOINTS=https://<node-a-onion>.onion:8800 \
# ... TLS and Tor variables same as step 4.1 ...
  cargo run --locked --features production -p kerosene-node
```

### 4.4 Verify quorum on both nodes

```bash
curl ... /ready-quorum
# → 200 OK (2 of 3 threshold met with 2 live members)
```

### 4.5 Start remaining Bank/Core nodes

Repeat step 4.3 for each additional bank node, adding all previous nodes to
`KEROSENE_GENESIS_ENDPOINTS`.

### 4.6 Start Vault nodes

Vault nodes use a separate plane and their own genesis trust entries.

```bash
KEROSENE_DISCOVERY_PLANE=vault \
KEROSENE_GENESIS_ENDPOINTS=https://<vault-a-onion>.onion:8800,... \
# ... all other variables with Vault-plane identity ...
  cargo run --locked --features production -p kerosene-node
```

Vault quorum requires at least threshold same-plane Vault members.

## 5. Full verification checklist

After all nodes are started:

```bash
# On every node
curl ... /live           → 200
curl ... /ready-local    → 200
curl ... /ready-member   → 200
curl ... /ready-quorum   → 200
curl ... /ready-financial → 200 (if applicable)

# Compare manifests
curl ... /v1/membership/current
# All nodes should return the same manifest hash for their plane.

# Operator diagnostics
cargo run -p kerosene-rsctl -- node status \
  --endpoint https://<node-a-onion>.onion:8800 \
  --output json-pretty

cargo run -p kerosene-rsctl -- node peers \
  --endpoint https://<node-a-onion>.onion:8800

cargo run -p kerosene-rsctl -- membership verify \
  --manifest current-manifest.json \
  --trust-bundle /path/to/genesis-trust-bundle.json
```

## 6. Ongoing operations

- Rotate TLS certificates before expiry (tracked separately from identity keys)
- Monitor health endpoints via a centralized dashboard
- Back up peer-store and identity keys after any membership change
- Run the load test suite (see `ops/LOAD_TEST_PLAN.md`) before capacity changes
- Practice cold start on a staging network before mainnet deployment
